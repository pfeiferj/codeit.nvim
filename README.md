# codeit.nvim

A small Neovim chat assistant with OpenRouter and experimental GitHub Copilot support. Requires Neovim 0.10+ and `curl` (developed with 0.12).

## Install and configure

Install this directory with your plugin manager (for example, `dir = '/path/to/codeit.nvim'` in lazy.nvim) and call:

```lua
require('codeit').setup({
  provider = 'openrouter', -- or 'copilot'
  models = {
    openrouter = 'openai/gpt-4o-mini',
    copilot = 'gpt-4o',
  },
  -- system_prompt = 'You are a helpful Neovim coding assistant.',
  -- max_tool_rounds = 12,
  -- max_context_tokens = 128000, -- optional manual override; false disables auto-compaction
  -- approval = {
  --   trusted_workspaces = {
  --     ['/absolute/path/to/project'] = 'all',     -- auto-approve reads inside this workspace
  --     ['/absolute/path/to/other'] = 'tracked',   -- auto-approve only Git-tracked file reads
  --   },
  --   validators = {
  --     function(name, args, context)
  --       -- return 'approve', 'ask', or 'reject', optionally with a reason
  --       if name == 'run_command' and args.argv and args.argv[1] == 'rm' then
  --         return 'reject', 'Deletion commands are disabled'
  --       end
  --       -- context.workspace and context.user_request are available here
  --     end,
  --   },
  -- },
})
```

For OpenRouter, set `OPENROUTER_API_KEY` in the environment before starting Neovim. Requests are sent to `https://openrouter.ai/api/v1/chat/completions` using OpenAI-compatible chat completions. Choose a model with tool-calling support to use editor tools.

For Copilot, authenticate with `gh auth login` or set `GH_TOKEN` / `GITHUB_TOKEN` to a GitHub token associated with a Copilot-enabled account. The plugin exchanges this token via GitHub's Copilot token endpoint, then sends requests to the Copilot chat completions endpoint. This integration uses GitHub's internal, undocumented API and may break or require different credentials; it is not the OpenRouter API and does not use an OpenRouter key.

## Use

- `:Codeit` toggles the single chat sidebar. The transcript and the multiline draft under `## Message` share a Markdown buffer; assistant replies retain Markdown formatting. Type below the heading and press `<CR>` in normal mode or `<C-s>` in insert mode to send; `<CR>` in insert mode inserts a newline. Press `q` in normal mode to close it.
- In the chat draft, type `/` at the start of the message to open the slash-command completion menu. Press Tab to complete the first matching command; press it again to cycle through the matches from the first Tab. Choose an entry and press Enter to run it (or `<CR>` in normal mode). For `/provider` or `/send`, Enter accepts the completion first so you can type a required argument; press Enter again to run it. Command results appear in the chat buffer without being sent to the assistant. Slash names are the Ex command names without `Codeit`, starting with a lowercase letter: for example, `/compact`, `/contextFull`, `/systemPrompt`, `/trustStatus`, and `/toggle` (for `:Codeit`). Commands with arguments also work, such as `/provider copilot`, `/trust tracked`, and `/send your question`. A single-line draft starting with `/` is treated as a command, not sent to the assistant; unknown commands remain in the draft for correction. Multiline messages and slashes elsewhere in a message are sent normally.
- `:CodeitSend your question` sends a message directly. `:CodeitSend` sends the draft currently at the bottom of the chat.
- `:CodeitNew` starts a fresh conversation and cancels outstanding responses or pending edits; previous chats remain in history.
- `:CodeitCompact` summarizes completed conversation turns using the current chat's provider and model (without tools). Future requests send the system prompt, this summary, and only newer turns; the full transcript stays visible and is saved for history. You can compact again after more turns to update the summary. The summary and its checkpoint survive resuming the chat. Compaction is unavailable while a response is in progress or a turn is unfinished; a failed or empty summary leaves the context unchanged. Summary requests may incur provider charges (included in OpenRouter usage totals).
- Automatic compaction detects the selected model's limit from OpenRouter's model catalog or Copilot's model metadata (using its prompt-token limit as a conservative ceiling). The result is cached per provider and model for the Neovim session. Set `max_context_tokens` to a positive number to override detection, or `false` to disable automatic compaction; manual `:CodeitCompact` still works. If the provider cannot supply a usable limit, the request proceeds without automatic compaction and a warning is shown once for that model. Before a chat request, compaction triggers when the **uncompacted** context (system prompt and messages since the last checkpoint) reaches 75% of the limit. It summarizes the oldest completed turns up to a turn boundary, retaining approximately the newest 50% of the window verbatim. The remaining 25% is reserved for the summary: existing summary text does not count toward the trigger, but is included in the next summary request and replaced by its result. An active user/tool turn is never split. Token counts are estimated at roughly four JSON characters per token; tool schemas and provider overhead are excluded, so use a conservative manual override if needed. If there is no eligible completed turn, compaction waits; if summarization fails, the original context is sent unchanged and a warning is shown.
- `:CodeitContext` shows the effective message context for the next request: system prompt, compacted summary (if present), and newer turns. Edit the summary and press `:w` or `<C-s>` to save it for future requests; press `q` to close. Other sections cannot be changed on save. Compact first if there is no summary. Edits persist when resuming the chat.
- `:CodeitContextFull` opens the **entire effective request context** as editable JSON (including system prompt, summary, messages, and tool metadata). Edit the message array and press `:w` or `<C-s>` to save, or `q` to close. The first entry must be a nonempty system prompt; tool calls must have matching results. Saving replaces the transcript with this effective context and clears the compaction checkpoint: earlier compacted turns are no longer in the chat, while the summary becomes an ordinary system message. Changes are saved to history and sent on the next request. Invalid JSON or changes to an out-of-date view are rejected.
- `:CodeitSystemPrompt` opens a plain-text editor for the current conversation's system prompt. Save with `:w` or `<C-s>`; an empty prompt is rejected. Changes to an existing chat persist across resume. Before the first message, the override applies only to this session; `:CodeitNew`, switching providers, or changing workspaces resets it to the configured prompt.
- `:CodeitHistory` lists saved chats for the current workspace (most recently updated first), showing each chat's last-updated date/time and LLM summary. For chats whose latest assistant turn has finished, it generates a brief description of what was done using that chat's saved provider and model before opening the picker. Each successful summary is cached in the chat file. Sending another question clears that cache; once the new turn finishes, history generates a fresh summary. Unfinished chats are shown with just their date/time. Select a chat in the wide, scrollable history window with `<CR>` to resume its transcript, provider, model, and usage totals; press `q` or `<Esc>` to dismiss it. Summary requests may incur provider charges and are not included in the chat's usage totals.
- `:CodeitProvider openrouter` / `:CodeitProvider copilot` switches providers and starts a fresh conversation.
- `:CodeitTrust` prompts you to trust the current workspace for **all files** or **Git-tracked files only**. `:CodeitTrust all` / `:CodeitTrust tracked` chooses directly. `:CodeitTrustStatus` shows the current mode; `:CodeitUntrust` revokes it. Choices persist across Neovim sessions.

Closing the sidebar does not discard the conversation. The source buffer for buffer tools is the file buffer active when the sidebar was opened. Agent workspace tools use Neovim's current working directory as the workspace root. Chats are saved automatically as they change under `stdpath('data')/codeit/chats/`, separated by resolved workspace path; files have mode `0600`. Changing workspaces starts a fresh chat without deleting the previous workspace's history. `:CodeitHistory` resumes a saved chat; incomplete tool-call batches from interrupted sessions are discarded on resume and are never re-executed. Requests are asynchronous but responses are not streamed.

The chat's cost/token usage line stays visible at the top of the transcript as you scroll. For OpenRouter it shows session cost in USD, cumulative input (`In`) and output (`Out`) tokens in millions (`m`) across chat and reviewer requests, and the latest main-chat response's context length (`Context`) in thousands (`k`; from `total_tokens` or input + output tokens). Immediately after compacting or editing the summary, `Context` updates to an approximate size of the effective message context, marked with `~`; the next main-chat response replaces it with reported usage. The estimate excludes tool definitions and uses roughly four characters per token. Displayed numbers have at most three decimal places. A `+` after a total means some requests omitted that usage field; `—` means the latest context is unavailable. Copilot does not show usage figures because its chat API does not report billed credits. `:CodeitNew`, switching providers, and `setup()` reset these figures for the new chat; resuming a saved chat restores its figures. Closing and reopening the sidebar preserves them.

## Agent tools

The assistant can:

- List and search workspace files (`list_workspace_files`, `search_workspace`; requires `rg`), and read files or loaded buffers (`read_file`, `list_buffers`, `read_buffer`). File reads include unsaved buffer contents; `read_file` reads to EOF by default and returns only available lines when a requested range extends past EOF.
- Edit existing file buffers (`edit_file`, `replace_buffer_lines`) or create a new file (`create_file`). Existing-file edits are **not saved** automatically; review and save them in Neovim. New files are created on disk in existing directories.
- Run builds, tests, or linters via `run_command` (argument vector, no implicit shell), inspect loaded-buffer diagnostics (`get_diagnostics`), and inspect workspace Git changes (`git_status`, `git_diff`). Git diff shows unstaged tracked changes, not untracked files or unsaved buffers.
- Fetch HTTP(S) URLs using `fetch_url` (`curl` required). This is not a web search engine or an MCP integration.

Read tools require approval by default. Use `:CodeitTrust` to trust Neovim's current working directory interactively; choices are stored in `stdpath('data')/codeit/trusted_workspaces.json` (mode `0600`). You can also set `approval.trusted_workspaces` to a map of absolute workspace directories to `'all'` or `'tracked'`; choices made with the commands override configuration for that workspace, including `:CodeitUntrust`. Trust applies only when the current workspace resolves to that directory; it does not extend to parent or child workspaces. In `'all'` mode, reads of files physically inside that workspace are auto-approved, including untracked files. In `'tracked'` mode, individual file/buffer reads are auto-approved only for Git-tracked files. Workspace-wide searches and file listings, unfiltered diagnostics, and Git status still ask in `'tracked'` mode because they can expose untracked content or names; Git diff and diagnostics for a tracked file are auto-approved. Buffer listings ask if any loaded named buffer points outside the allowed files. Symlinks to files outside the trusted workspace always ask. Trust is granted explicitly; there is no implicit trust for the plugin's own directory.

Edits, creation, commands, URL fetches, and unknown tools require approval in either mode. Standard Markdown approval prompts show the tool name in bold above formatted arguments: pretty-printed JSON for ordinary calls, or a shell-quoted `bash` fence for `run_command`'s argument vector (shown for readability; the command is still executed without an implicit shell). Non-write approvals make a separate tool-free reviewer request to summarize the call and assess its safety. The summary is shown in the Markdown approval window (bold if unsafe), or marked unavailable if review fails. Write calls (`edit_file`, `replace_buffer_lines`, `create_file`) instead open a dedicated popup without waiting for an automatic summary. It shows the entire proposed file with source syntax highlighting; removed lines appear in red next to added lines in green, without patch headers or `+`/`-` prefixes. Centered virtual text keeps the approval shortcuts pinned to the top while scrolling; `{` and `}` jump between changed regions, wrapping at the ends. Press `5` to ask the tool-free reviewer about the change; it receives the proposed patch, and returning from the reviewer brings back the full-file preview. Review is advisory and never auto-approves a call; policy-rejected and auto-approved calls do not incur a review request. In the standard Markdown approval window, move to a choice and press `<CR>` in normal mode to select it, or use the number shortcuts: `1` **Approve once**, `2` **Always approve exact call**, `3` **Reject** (with an optional explanation sent back to the agent), and `4` **Cancel task**. On read-tool prompts, `5` **Trust workspace (Git-tracked reads)** or `6` **Trust workspace (all reads)** saves that choice for the current workspace and approves the pending read; it does not auto-approve edits or commands. **Ask reviewer** is `5` on other prompts and `7` on read prompts when available. Press `<Esc>`, or close the approval window, to reject the call. The reviewer opens a single Markdown window showing the tool name, arguments, conversation, and a multiline draft under `## Question`. Type below the heading and press `<C-s>` (in insert or normal mode), or `<CR>` in normal mode, to send. A waiting indicator appears until the reply is added to the conversation. Type another question below the heading to follow up. Press `<Esc>` in normal mode or close the reviewer window to return to approval; empty questions are ignored. The reviewer is a separate, tool-free conversation with the configured model. Cancelling stops the task and drops its unfinished tool-call batch, leaving earlier conversation intact.

Always-approved signatures include the workspace's resolved path, tool name, and full arguments (independent of JSON object key order); their hashes are saved across Neovim sessions in `stdpath('data')/codeit/approvals.json`. Explicit per-call approvals remain effective even if workspace trust changes; delete that file to revoke saved approvals. Configure `approval.validators` in `setup()` with functions receiving `(name, args, context)` that return `'approve'`, `'ask'`, `'reject'`, or `nil`, optionally with a reason. Validators run for **every** call, including saved approvals; rejection wins over asking, and asking wins over approval or saved/default auto-approval. Errors or invalid decisions reject the call.

Buffer edits check for changes while confirmation is pending; file paths are restricted to the current workspace, including symlink targets. Commands run in that workspace but, once approved, can access the wider system. Command outputs are bounded; `read_file` can return a whole file, so specify line ranges for large files. Use smaller searches when needed. This is a local approximation of common VS Code Copilot Agent capabilities, not VS Code's exact or extension-provided tool set.

Run all headless tests from the repository root with `sh tests/run.sh`. The runner isolates saved approvals in a temporary data directory and exits with an error if a suite fails.
